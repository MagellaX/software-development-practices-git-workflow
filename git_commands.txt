GIT COMMAND DOCUMENTATION

This record follows the website repository from its first snapshot to publication.
The HTML edits took place between the relevant add and commit commands; GitHub was created afterwards.

01. git init -b main
    Start version tracking in the already-created website directory. The -b option selects main immediately.

02. git config user.name MagellaX
    Give commits in this website repository the author label MagellaX; other repositories keep their settings.

03. git config user.email 144127816+MagellaX@users.noreply.github.com
    Associate the public commits with the account noreply address rather than exposing a personal mailbox.

04. git add index.html about.html
    Place both HTML pages in the index so the first snapshot contains the linked pair.

05. git commit -m "Initial commit: add home and about pages"
    Save the two-page starting point as e2ff534, before any introduction or features-list edits.

06. git add index.html
    Select the edited introduction in index.html for the next snapshot; about.html is unchanged here.

07. git commit -m "Update home page introduction"
    Save the introduction revision as df04dbc. This establishes a second main-branch state before branching.

08. git branch feature
    Add a branch pointer at df04dbc. Creating this pointer alone does not change the checked-out branch.

09. git switch feature
    Check out that pointer so the upcoming about-page commit advances feature rather than main.

10. git add about.html
    Put the new about-page features list into the index while feature is checked out.

11. git commit -m "Add project features to about page"
    Save the features-list work as 616150d; this is the commit retained by the feature branch.

12. git switch main
    Check out main again, selecting the destination into which the about-page work will be combined.

13. git merge --no-ff feature -m "Merge feature branch into main"
    Produce merge 613c8cf. --no-ff deliberately keeps a two-parent merge even though a fast-forward was possible.

14. git log --graph --oneline --all --decorate
    Draw the relationship between df04dbc, feature commit 616150d and their merge; decorations identify branch pointers.

15. git check-ignore -v debug.log temp/scratch.txt
    Ask which exclusion rule matches each sample path. The returned line numbers distinguish *.log from temp/.

16. git add .gitignore
    Select the exclusion configuration itself for tracking, while leaving the sample log and scratch file outside Git.

17. git commit -m "Ignore log files and temp folder"
    Store the two exclusion patterns in 229cd30 so another checkout receives the same rules.

18. git add index.html
    Select the one-line announcement added specifically to demonstrate recovery from an unwanted change.

19. git commit -m "Add temporary announcement for undo demonstration"
    Save that announcement as 4abf0e5. Its recorded insertion supplies a concrete change to reverse.

20. git show --stat --oneline HEAD
    Inspect the then-current announcement snapshot: the summary reports one added line in index.html.

21. git revert --no-edit HEAD
    Apply the opposite of the then-latest change. --no-edit accepts the generated message, producing 7a24509.

22. git show --format=short HEAD -- index.html
    Read the recovery patch: the minus-prefixed announcement line confirms what was taken out of index.html.

23. git status --short
    Check for remaining index or worktree differences. Here the command returned no lines after recovery.

24. git add README.md git_commands.txt
    Select the usage note and this command record so both become part of the published project.

25. git commit -m "Document Git workflow commands"
    Save the first documentation version as 75ec7cb, following the completed merge, exclusions and recovery.

26. gh repo create MagellaX/software-development-practices-git-workflow --public --source . --remote origin --description "Local Git workflow demonstration with branching, merging, ignore rules, and revert."
    Use GitHub CLI to create the remote only after the local work; --public sets visibility and --remote names it origin.

27. git remote -v
    Inspect both configured endpoints and confirm they identify the MagellaX assignment repository.

28. git push -u origin main
    Send main and its reachable commits to GitHub; -u remembers origin/main for subsequent status and push commands.

29. git push -u origin feature
    Send the still-retained feature pointer too, allowing a reviewer to inspect the branch directly on GitHub.

30. git log --graph --oneline --all --decorate
    Recheck the graph after publication. origin/main and origin/feature now appear beside their local counterparts.

31. git status --short --branch
    Read the branch relationship together with worktree status; main...origin/main was the only output line.

32. git ls-remote --heads origin
    Query the server branch pointers directly and compare their hashes with the local history.

SUPPLEMENTARY EVIDENCE COMMANDS
The checks below produced the terminal screenshots after the main exercise. Descriptions were clarified later; recorded commands and hashes are unchanged.

git ls-files
    Enumerate the files Git actually records; this separates tracked website files from the ignored examples.

git --no-pager log --graph --oneline --all --decorate
    Print the evidence graph directly in the console so its branch relationships fit in a screenshot.

git --no-pager show --no-patch --format=short --pretty=raw 613c8cf
    Expose the two parent fields of 613c8cf without printing the HTML patch.

git --no-pager show HEAD:.gitignore
    Read the saved configuration from Git rather than relying only on the current working copy.

git --no-pager show --stat --oneline 4abf0e5
    Inspect the announcement by its stable hash, even after HEAD has advanced beyond the recovery operation.

git --no-pager show --format=short 7a24509 -- index.html
    Inspect the recovery by its stable hash and limit the output to the affected page.

git branch -avv
    Compare the tips of local branches with the fetched remote references in the captured evidence.

gh repo view --json url,visibility,defaultBranchRef
    Retrieve machine-readable GitHub properties; PUBLIC verifies that the project is viewable without repository access.

git add git_commands.txt
    Select the additional screenshot-verification notes for the next documentation snapshot.

git commit -m "Document terminal evidence verification commands"
    Record those added notes as d250adf, which is the main-branch tip visible in the terminal screenshots.

git push origin main
    Send the documentation snapshot to the existing remote without changing the feature pointer.
